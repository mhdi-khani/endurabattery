# Endura Battery — راهنمای نصب V8

## وضعیت و محدوده
این نسخه شامل کل ریپازیتوری استاتیک Endura Battery به همراه فایل‌های جدید، صفحات فروشگاهی، CMS و پنل‌های موجود است. بخش‌های **محصولات و محتوا** همچنان از Supabase استفاده می‌کنند. در این نسخه **حساب مشتری، پروفایل، آدرس‌ها و دارایی‌ها** به Supabase Auth و RLS وصل شده‌اند. **درخواست پیگیری خرید** برای کاربر واردشده در جدول `purchase_inquiries` ذخیره می‌شود؛ این یک سفارش نهایی یا پرداخت بانکی نیست.

## راه‌اندازی GitHub
1. ZIP را باز کنید و **محتوای** پوشه `endura-battery-site` را در ریشه ریپازیتوری قبلی جایگزین کنید.
2. GitHub Pages باید از workflow موجود در `.github/workflows/pages.yml` منتشر شود.
3. آدرس‌های `/#/shop`، `/#/category/light`، `/#/checkout`، `/#/account/profile`، `/#/admin/inquiries` و یک آدرس نامعتبر مانند `/#/unknown-test` را بررسی کنید.
4. `404.html` برای مسیر نامعتبر GitHub Pages نیز در ریشه پروژه وجود دارد.
5. اگر فایل‌های CSS/JS قدیمی از کش نمایش داده شدند، Hard Refresh بزنید.

## فعال‌سازی دیتابیس
1. در Supabase > SQL Editor و **بعد از Migrationهای نسخه‌های قبلی** فایل `supabase/migrations/20261103000000_customer_inquiries.sql` را اجرا کنید.
2. جدول‌های `customer_profiles`، `customer_assets` و `customer_addresses` از Migration اولیه موجودند. اگر وجود ندارند، ابتدا Migrationهای اصلی را به ترتیب اجرا کنید؛ تنها Migration جدید برای اطلاعات درخواست خرید کافی نیست.
3. در Table Editor باید جدول `purchase_inquiries` دیده شود. برای بررسی RLS، کاربر معمولی فقط داده‌های متعلق به خودش را می‌بیند؛ مدیر دارای نقش معتبر `admin` دسترسی خواندن دارد.
4. در Authentication > Providers روش Email را فعال نگه دارید. اگر Confirm email فعال است، کاربران باید لینک ایمیل را تأیید کنند.
5. در Authentication > URL Configuration، URL منتشرشده GitHub Pages را به Site URL و Redirect URLs مجاز اضافه کنید (مثلاً `https://USERNAME.github.io/REPOSITORY/**`). لینک بازگشت احراز هویت باید به همان دامنه عمومی اشاره کند.
6. در `/#/account/profile` یک کاربر جدید ایجاد کنید، ایمیل را تأیید کنید، وارد شوید و نام و تلفن را ذخیره کنید. بعد از Refresh باید اطلاعات از Supabase دوباره بارگذاری شود.
7. صفحه `/#/admin/inquiries` برای مدیر دارای نقش `admin`، درخواست‌های خریدِ **کاربران احراز هویت‌شده** را نشان می‌دهد. کاربران معمولی اجازه مشاهده درخواست‌های دیگران را ندارند.

## اتصال Apps Script بدون تغییر کد اسکریپت
در `assets/js/lead-webhook.js` از همین URL عمومی استفاده شده است:

`https://script.google.com/macros/s/AKfycby9WcUxmusBfaUzy7EiFj1cmyXdGEPAHayVRB0rN43SnomdnGDTk12T9lN2F6L6dft6/exec`

کد Apps Script شما دست‌نخورده مانده. در خود Google Apps Script مطمئن شوید Web App با گزینه **Execute as: Me** و **Who has access: Anyone** منتشر شده، مجوزهای Sheets و ارسال ایمیل تأیید شده و در صورت اصلاح بعدی خود اسکریپت، نسخه جدید Deploy شده باشد.

فیلدهای ضروری اسکریپت: `name`، `email` و `message`. نام، ایمیل و سایر داده‌ها با همان ساختار وارد می‌شوند. تلفن، موضوع درخواست، محصولات، خدمات و شهر در `message` قرار می‌گیرند. **رمز عبور، اطلاعات کارت یا داده‌های نشست احراز هویت ارسال نمی‌شوند.** ارسال به Google Sheets / ایمیل منوط به تأیید رضایت در فرم است.

**محدودیت CORS:** سایت استاتیک درخواست را با `no-cors` و `text/plain` می‌فرستد تا Apps Script بتواند JSON متن را بخواند. مرورگر پاسخ قابل بررسی دریافت نمی‌کند؛ پس موفقیت نهایی ثبت در Google Sheet قابل تأیید خودکار نیست. حداقل یک ثبت‌نام و فرم تست با رضایت ارسال کنید و ردیف Sheet / ایمیل را دستی کنترل کنید.

**مقصد ایمیل اعلان در خود Apps Script:** `sirmhdikhani@gmail.com` است؛ چون خواسته‌اید کد Apps Script تغییر نکند، آن را عوض نکردیم. با انتشار URL عمومی و سطح دسترسی Anyone، خطر ارسال هرزنامه وجود دارد؛ برای استفاده گسترده Rate Limiting و محافظت سروری مناسب است.

## حساب مشتری
- `/ # /account/profile` (بدون فاصله، یعنی `/#/account/profile`): ورود/ثبت‌نام با ایمیل و رمز Supabase.
- نام، موبایل و ایمیل در `customer_profiles`.
- خودروها/تجهیزات و نشانی‌ها در `customer_assets` و `customer_addresses`.
- ایمیل از فرم پروفایل به‌صورت مستقیم تغییر نمی‌کند؛ تغییر آن نیازمند فرایند تایید Supabase است.
- در فرم مرحله دوم Checkout دکمه «ثبت درخواست تماس برای خرید (بدون پرداخت)» اضافه شده. در صورت ورود کاربر، درخواست در Supabase ثبت می‌شود. اگر بدون ورود باشد، فقط با رضایت کاربر تلاش برای ارسال Google Sheets انجام می‌شود.

## اصلاحات ظاهری
- `/ # /shop` و چهار دسته: پنل فیلتر موبایل با عرض سازگار، زمینه تیره خوانا، بستن با دکمه و پس‌زمینه و بدون اسکرول افقی در نمونه مستقل.
- در Dark Mode جفت رنگ‌های پس‌زمینه و نوشته برای دکمه‌ها، عناصر حساب کاربری، Checkout، جداول و پنل‌ها یکپارچه‌تر شده‌اند.
- صفحه 404 از `Endura_404_05_Dark_Light_Responsive.html` ساخته شده و در `404.html` حفظ شده است؛ جست‌وجوی آن به `/#/search?q=...` هدایت می‌شود.
- عبارت تزئینی `BLOOM / 01` و برچسب‌های اضافی از Loader حذف شده‌اند.
- در نمای دسکتاپ Smart Skeleton، کادر بصری Hero در سمت راست و متن در سمت چپ قرار می‌گیرد.

## محدودیت‌ها و تست
- درگاه بانکی، پرداخت واقعی و سفارش نهایی هنوز نیازمند بک‌اند و پیاده‌سازی ایمن‌اند؛ نسخه حاضر هیچ پرداخت موفق یا سفارش قطعی ثبت نمی‌کند.
- تست نحوی فایل‌های JavaScript و تست ایستای CSS روی 320، 390، 768، 1024 و 1440 پیکسل اجرا شده‌اند. مرورگر در این محیط دسترسی به سایت محلی/منتشرشده نداشت؛ بنابراین آزمون یکپارچه روی Supabase زنده و ارسال واقعی Apps Script اجرا نشده است.
- قبل از انتشار عمومی، کنترل کنید که حساب مشتری A اطلاعات مشتری B را نمی‌بیند و برعکس؛ RLS باید فعال باشد.
